## Как работает DBSCAN

### Что это

DBSCAN (Density-Based Spatial Clustering of Applications with Noise) —
алгоритм кластеризации, который находит группы плотно расположенных точек
и отделяет их от разреженного шума.

В нашем случае задача: из облака точек, где есть объект + фон (трава, стены,
мусор) — оставить только точки объекта.

### Два параметра

| Параметр | Значение | Что означает |
|----------|----------|--------------|
| `eps` | авто (~3× средний шаг) | радиус поиска соседей |
| `min_points` | 10 | минимум соседей чтобы точка была «ядром» кластера |

**Адаптивный eps** — не задаётся вручную, вычисляется из размеров облака:

```
eps = (diagonal_bbox / sqrt(N)) × factor
```

Это масштабируется под любой объект независимо от расстояния до камеры.

### Как работает (реальный код: `point_cloud.cpp`, строки 483–574)

```
Для каждой непомеченной точки i:
  1. Найти всех соседей в радиусе eps (через KD-tree)
  
  2. Если соседей < min_points → точка = ШУМ (метка -2)
  
  3. Если соседей >= min_points → начать новый кластер:
     - Пометить точку i меткой кластера
     - Добавить соседей в BFS-очередь
     
     BFS-обход:
       Для каждой точки из очереди:
         - Найти её соседей в радиусе eps
         - Если у неё соседей >= min_points (ядровая точка):
             добавить новых непомеченных соседей в очередь
         - Если соседей < min_points (граничная точка):
             входит в кластер, но НЕ расширяет его
```

### Что возвращается

После кластеризации выбираются все кластеры, размер которых ≥ `min_cluster_fraction` от наибольшего.
Шумовые точки (метка -2) отбрасываются.

```
Пример (tst7, кролик в саду):
  До DBSCAN:  ~1 400 000 точек (объект + газон + деревья)
  После:        880 019 точек (кролик)
  Удалено:      58.5% — фон
```

### Типы точек

```
● Ядровая точка — соседей >= min_points, расширяет кластер
○ Граничная точка — соседей < min_points, входит в кластер соседа
✕ Шум — не входит ни в один кластер
```

## Как создаётся меш из облака точек

### Шаг 1 — Оценка нормалей (PCA)

Перед построением меша каждая точка должна знать «в какую сторону» направлена
поверхность. Нормаль вычисляется через анализ главных компонент (PCA):

```
Для точки p:
  1. Найти k=30 ближайших соседей (KD-tree)
  2. Вычислить ковариационную матрицу 3×3 по окрестности
  3. Найти собственные векторы (Eigen::SelfAdjointEigenSolver)
  4. Нормаль = собственный вектор с НАИМЕНЬШИМ собственным значением
     (это направление наименьшего разброса = перпендикуляр к поверхности)
  5. Проверить ориентацию: если нормаль смотрит «внутрь» (от центра масс) — перевернуть
```

Реализация: `point_cloud.cpp`, строки 439–477.

### Шаг 2 — Poisson Surface Reconstruction

Алгоритм Kazhdan & Hoppe (2013). Идея: найти такую поверхность, которая
наилучшим образом «объясняет» данное облако нормалированных точек.

```
Входные данные: point_cloud_clean.ply (точки + нормали)

Математика:
  1. Облако точек интерпретируется как выборка с поверхности неизвестного тела
  2. Строится индикаторная функция χ (1 внутри тела, 0 снаружи)
  3. Поверхность = изоповерхность χ при значении 0.5

Параметр depth (7 / 9 / 11):
  - Определяет разрешение октарного дерева (octree)
  - depth=7  → грубый меш, мало деталей, быстро (~15 мин)
  - depth=9  → средний меш (наш дефолт, ~90 мин)
  - depth=11 → детальный меш, много граней (~3 часа)
```

Вызов через COLMAP `poisson_mesher`:
```python
ColmapRunner(config).poisson_mesh(clean_ply, out_ply, depth=9)
```

Результат: `mesh_raw.ply` — сырой меш с возможными дефектами.

### Шаг 3 — Ремонт меша (MeshRepair, C++)

Poisson-меш часто содержит дефекты. Применяем 6 операций подряд:

| № | Операция | Что исправляет |
|---|----------|----------------|
| 1 | `remove_degenerate_faces` | Грани с нулевой площадью (3 точки на одной прямой) |
| 2 | `remove_duplicate_faces` | Одинаковые грани, записанные дважды |
| 3 | `merge_close_vertices` | Вершины, расстояние между которыми < порога |
| 4 | `make_manifold` | Рёбра, принадлежащие >2 граням (невалидная топология) |
| 5 | `fill_holes` | Незакрытые контуры — fan-triangulation от центроида |
| 6 | `laplacian_smooth` | Шероховатость поверхности (3 итерации, граница фиксирована) |

#### Как работает закрытие дыр (fill_holes)

```
1. Найти граничные рёбра: каждое ребро (a→b) без обратного (b→a)
2. Построить граничный контур: boundary_next[b] = a, обойти петлю
3. Вычислить центроид контура
4. Заполнить дыру: для каждого ребра контура создать грань
   (centroid, boundary[i], boundary[i+1])
```

#### Laplacian smoothing

Каждая вершина смещается к среднему положению своих соседей:

```
v_new = v + λ × (среднее(соседи) − v),  λ = 0.5

Граничные вершины НЕ смещаются (иначе дыры расширяются)
```

### Шаг 4 — pymeshfix

Финальная зачистка через pymeshfix, если меш всё ещё не watertight
(есть незакрытые рёбра). Проверяет `is_watertight` перед запуском —
если меш уже водонепроницаем, пропускает.

```
Пример результата (tst7):
  Вершин:  291 850
  Граней:  584 612
  Дыры:    0
  Watertight: Да
```

## Стек технологий

| Компонент | Технология | Зачем |
|-----------|-----------|-------|
| SfM + MVS | COLMAP (готовые .exe) | Восстановить позиции камер и плотное облако |
| Фильтрация облака | C++17 + nanoflann | SOR, DBSCAN через KD-tree, производительность |
| Линейная алгебра | Eigen3 | PCA для нормалей, матрицы трансформаций |
| Poisson меш | COLMAP poisson_mesher | Строит поверхность из облака с нормалями |
| Ремонт меша | C++ MeshRepair | Контроль над каждой операцией |
| Финальная зачистка | pymeshfix | Watertight меш |
| Python-пайплайн | Python 3.11 + pathlib | Оркестрация всех шагов |
| Биндинги C++↔Python | pybind11 | Вызов C++ кода из Python без overhead |
| API | FastAPI + SSE | Прогресс в реальном времени |
| Интерфейс | Three.js r165 | 3D в браузере |
| БД истории | SQLite | Сохранение результатов сканов |
